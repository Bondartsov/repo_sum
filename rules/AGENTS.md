# Правила и инструкции для агентов

## 🎯 Введение и цель документа

Этот документ содержит единые инструкции для всех агентов (AI-помощников), работающих с проектом repo_sum. Документ является обязательным руководством для всех участников разработки.

### 1.1 Назначение
Настоящий документ устанавливает единые стандарты и правила работы для всех агентов (AI-помощников) в проекте repo_sum. Цель - обеспечение консистентности, качества кода и эффективной разработки.

### 1.2 Область применения
Инструкции применяются ко всем видам работ:
- Разработка нового функционала
- Рефакторинг существующего кода
- Написание и обновление документации
- Тестирование и отладка
- Архитектурное проектирование

### 1.3 Обязательность соблюдения
**Все агенты ОБЯЗАНЫ следовать данным инструкциям без исключений.** Отклонения допускаются только с явного одобрения технического лидера проекта.

**Команды в теримнале запускать под powershell, мы работаем в среде windows**

## 5. Стандарты кода и архитектуры

### 5.1 Архитектурные принципы
- **RAG-as-a-Service** архитектура
- **Гибридный поиск**: dense (FastEmbed) + sparse (BM25 + кастомный sparse-энкодер)
- **CPU-first оптимизация** - GPU не требуется
- **Сервис ориентрованная архитектура** с четким разделением ответственности

### 5.2 Ключевые компоненты
- **RAGFactory** - **[rag/factory.py](rag/factory.py)** (Единственная точка входа!)
- **Гибридный эмбеддер** - **[rag/embedder.py](rag/embedder.py)**
- **Векторное хранилище** - **[rag/vector_store.py](rag/vector_store.py)**
- **Поисковый сервис** - **[rag/search_service.py](rag/search_service.py)**

### 5.3 Файловая структура
```
├── main.py                    # Точка входа
├── config.py                  # Конфигурация
├── rag/                       # RAG модули
│   ├── factory.py            # ⚠️ Фабрика компонентов (Context-Aware)
│   ├── remote_embedder.py    # HTTP клиент эмбеддингов
│   ├── remote_vector_store.py# HTTP клиент поиска
│   └── ...
├── parsers/                   # Парсеры кода
├── tests/                     # Тесты
├── rules/                     # Правила и документация
└── scripts/                   # Скрипты обслуживания
```

### 5.4 Правила работы с RAG (CRITICAL)
1. **ТОЛЬКО RAGFactory**: Запрещено напрямую создавать экземпляры `QdrantVectorStore`, `CPUEmbedder` или `RemoteVM*`.
   - ✅ `embedder = RAGFactory.create_embedder(config)`
   - ❌ `embedder = CPUEmbedder(config)`
2. **Context-Awareness**: Фабрика сама определит, где запущен код (VM или Client). Не пытайтесь хардкодить логику выбора.
3. **Async-Safe**: Все вызовы к RAG должны быть обернуты в `run_async_safe` (для синхронного кода) или `await` (для асинхронного).

## 6. Правила тестирования

### 6.1 Общие требования
- **Offline/mock режим обязателен**
- **Все сетевые вызовы должны быть замоканы**
- **Строгая категоризация**: unit, integration, e2e, property-based
- **Property-based тесты** через `hypothesis`

### 6.2 Специфические команды
```bash
# Запуск всех RAG тестов
pytest tests/rag/

# Специальный раннер для RAG модулей
python tests/rag/run_rag_tests.py

# Проверка offline режима
python tests/test_offline_no_network.py
```

### 6.3 Требования к покрытию
- **Unit тесты**: минимум 90% покрытия
- **Integration тесты**: все критические пути
- **E2E тесты**: основные пользовательские сценарии
- **Property-based тесты**: edge cases и граничные условия

### 6.4 Mock правила
См. **[Technical Architecture.md](Technical Architecture.md)** для детальных правил создания mock объектов.

## 10. Работа с VM (Virtual Machine)

### 10.1 Архитектура VM
Проект использует **RAG-as-a-Service** архитектуру с удаленной VM:
- **VM адрес**: 10.61.11.54:22 (SSH)
- **RAG сервис**: http://10.61.11.54:8000
- **Qdrant**: http://10.61.11.54:6333
- **Репозиторий на VM**: ~/repo_sum_rag/repo_sum

### 10.2 Workflow разработки с VM

**Стандартный цикл работы:**

```bash
# 1. Локально вносите изменения в код
# Редактируйте файлы, добавляйте функционал

# 2. Коммитьте изменения
git add .
git commit -m "Описание изменений"
git push

# 3. Синхронизация с VM (автоматически)
python vm_start.py update

# 4. Проверка статуса RAG системы
python main.py rag status

# 5. Запуск веб-интерфейса (опционально)
python run_web.py
```

### 10.3 Что делает `vm_start.py`

**Автоматические операции при запуске:**

1. 🔗 SSH подключение к VM (10.61.11.54)
2. 📁 Синхронизация кода через `git pull` из GitHub
3. 🐍 Обновление Python окружения (`pip install -r requirements.txt`)
4. ⚙️ Обновление .env файла (37 переменных окружения)
5. 🧪 Тест загрузки Jina v3 модели
6. 🚀 **Автоматический запуск RAG сервиса** через `nohup python vm_rag_service.py &`
7. ✅ Проверка health check всех сервисов

**Важно:** НЕ нужно вручную заходить на VM и запускать `vm_rag_service.py`!

### 10.4 Команды для работы с VM

```bash
# Полная настройка VM (первый запуск или после перезагрузки)
python vm_start.py

# Быстрое обновление кода на VM
python vm_start.py update

# Проверка статуса RAG системы
python main.py rag status

# Проверка статуса с подробностями
python main.py rag status --detailed

# Индексация репозитория в RAG
python main.py rag index <путь_к_репозиторию>

# Поиск по коду
python main.py rag search "authentication"

# Веб-интерфейс для RAG
python run_web.py
```

### 10.5 Troubleshooting VM

**Проблема: RAG сервис не отвечает**
```bash
# 1. Проверить статус
python main.py rag status

# 2. Перезапустить VM setup
python vm_start.py

# 3. Проверить логи на VM (если нужно)
# ssh user@10.61.11.54
# tail -f ~/repo_sum_rag/repo_sum/rag_service.log
```

**Проблема: Код на VM не обновился**
```bash
# Принудительная синхронизация
python vm_start.py update

# Проверить версию кода на VM (видно в выводе)
# Должно быть: "jina-embeddings-v3 @ <commit_hash>"
```

**Проблема: `python main.py rag status` не работает**
- Проверьте, что файлы не содержат BOM символы
- Проверьте, что файлы не пустые: `git status`
- Восстановите из git если нужно: `git checkout HEAD -- main.py`

### 10.6 Важные особенности VM

**Автоматизация:**
- VM сервисы запускаются автоматически через `vm_start.py`
- Не требуется ручное управление процессами на VM
- Git синхронизация происходит автоматически

**Мониторинг:**
- `vm_start.py` показывает таблицу статуса всех компонентов
- `python main.py rag status` показывает health check
- Jina v3 тест проверяет корректность загрузки модели

**Безопасность:**
- SSH ключи должны быть настроены
- .env файл синхронизируется с VM
- Не храните секреты в коде - только в .env!
