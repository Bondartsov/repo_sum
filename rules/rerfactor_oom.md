# План рефакторинга `rerfactor_oom.md`
**Тема:** системная оптимизация RAM при первичной индексации кода (RAG-пайплайн: чанкование → эмбеддинги → Qdrant)  
**Контекст:** OOM-killer завершает процесс `python` на ВМ c uvicorn при генерации эмбеддингов (anon-rss ≈ 64ГБ). Клиент получает `ConnectionRefusedError` на `10.61.11.54:8000`.  
**Цель:** устранить OOM и стабилизировать индексацию без заметной деградации качества поиска кода. Без жёсткой квантизации качества (INT8 — опционально, по флагу).

---

**ВАЖНО** код на ВМ обновляется только через скрипт vm_start.py (можно черрез флаг update). Перед запуском обязательно запушить изменений в GIT, скрипт синхронизирует текущую ветку с кодом на ВМ. Но во время выполнения скрипта надо вручную выбрать ветку. Текущая ветка - oom_refactor

## Примечания по качеству (почему это безопасно)
- Лимит токенов и стримовая индексация **не ухудшают** модель — они только нормализуют вход и уменьшают пик RAM.  
- `truncate_dim` (матрешка) снижает размер вектора, но сохраняет упорядоченность компонент — потери качества минимальны (подтверждать A/B-тестом).  
- Мы **не** включаем INT8 по умолчанию: риск деградации переносим в отдельный флаг и только через эксперименты.
