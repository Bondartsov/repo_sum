## 3. Требования к языку и стилю

### 3.1 Код
- **Строгое соблюдение PEP8**
- **Обязательная типизация** (type hints)
- **SOLID принципы** во всех модулях
- **DRY (Don't Repeat Yourself)** - избегать дублирования кода
- **Fail-fast валидация** - ошибки должны выявляться максимально рано
- **KISS** - "Keep it simple stupud" - подход!

### 3.2 Комментарии
- **ВСЕГДА** комментировать сложную логику на русском языке
- **ВСЕГДА** документировать на русском языке публичные функции и классы
- **ВСЕГДА** объяснять назначение модулей
- **ВСЕГДА** указывать автора изменений и дату

### 3.3 Документация
- **Markdown** формат для всех документов
- **Структурированный** подход с оглавлением
- **Ссылки** на связанные документы
- **Примеры** использования в документации API

## 5. Стандарты кода и архитектуры

### 5.1 Архитектурные принципы
- **RAG-as-a-Service** архитектура
- **Гибридный поиск**: dense (FastEmbed) + sparse (BM25 + кастомный sparse-энкодер)
- **CPU-first оптимизация** - GPU не требуется
- **Сервис ориентрованная архитектура** с четким разделением ответственности

### 5.2 Ключевые компоненты
- **Jina v3 embeddings** (570M параметров) - **[JINA_V3_VM_MIGRATION_PLAN.md](JINA_V3_VM_MIGRATION_PLAN.md)**
- **Гибридный эмбеддер** - **[rag/embedder.py](rag/embedder.py)**
- **Векторное хранилище** - **[rag/vector_store.py](rag/vector_store.py)**
- **Поисковый сервис** - **[rag/search_service.py](rag/search_service.py)**

### 5.3 Файловая структура
```
├── main.py                    # Точка входа
├── config.py                  # Конфигурация
├── rag/                       # RAG модули
│   ├── embedder.py           # Гибридный эмбеддер
│   ├── vector_store.py       # Векторное хранилище
│   └── search_service.py     # Поисковый сервис
├── parsers/                   # Парсеры кода
├── tests/                     # Тесты
├── rules/                     # Правила и документация
└── scripts/                   # Скрипты обслуживания
```

## 6. Правила тестирования

### 6.1 Общие требования
- **Offline/mock режим обязателен**
- **Все сетевые вызовы должны быть замоканы**
- **Строгая категоризация**: unit, integration, e2e, property-based
- **Property-based тесты** через `hypothesis`

### 6.2 Специфические команды
```bash
# Запуск всех RAG тестов
pytest tests/rag/

# Специальный раннер для RAG модулей
python tests/rag/run_rag_tests.py

# Проверка offline режима
python tests/test_offline_no_network.py
```

### 6.3 Требования к покрытию
- **Unit тесты**: минимум 90% покрытия
- **Integration тесты**: все критические пути
- **E2E тесты**: основные пользовательские сценарии
- **Property-based тесты**: edge cases и граничные условия

### 6.4 Mock правила
См. **[Technical Debt.md](Technical Debt.md)** для детальных правил создания mock объектов.
