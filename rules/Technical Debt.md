## 🚨 Критические проблемы (P0 - блокируют production)

### **P0-1. Критическая проблема таймаутов при RAG индексации**
**Статус:** ✅ ЗАВЕРШЕНО (16 января 2026)
**Решение:** Реализован `RetryPolicy` с учетом `deadline`. Теперь каждый запрос знает, сколько времени у него осталось от общего лимита. Конфигурация `config.remote_service.timeout_seconds` теперь является приоритетной.

---

### **P0-2. Qdrant Vector Store показывает статус "error"**
**Статус:** ✅ ЗАВЕРШЕНО (16 января 2026)
**Решение:**
1.  В `main.py` исправлена логика отображения цветов: статусы `ok`, `connected`, `healthy` теперь корректно подсвечиваются зеленым.
2.  В `rag/remote_vector_store.py` улучшен `_async_health_check`: добавлена проверка статуса самого Qdrant (`qdrant_status`). Если HTTP 200, но Qdrant не готов, возвращается статус `degraded` с диагностикой.
3.  CLI теперь выводит детальную таблицу диагностики при проблемах.

---

### **P0-3. Неверное отображение статуса Qdrant "ok" красным цветом**
**Статус:** ✅ ЗАВЕРШЕНО (16 января 2026)
**Решение:** Исправлено в рамках задачи P0-2. Добавлена явная проверка `vs_status in ('connected', 'ok', 'healthy')`.

---

### **P0-4. Code Chunker: "I/O operation on closed file"**
**Статус:** ✅ ЗАВЕРШЕНО (16 января 2026)
**Решение:** Все вызовы `print()` в `code_chunker.py` заменены на `logger.info()`. Использование стандартного логгера предотвращает ошибки при работе в средах с перенаправленными потоками (VM, Docker).
