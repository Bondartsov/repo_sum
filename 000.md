#### 🧨 **2. Ключевые симптомы**

##### **A. Ошибка в логах ВМ (серверной части RAG):**
```
ERROR - Ошибка поиска: SearchService.search() got an unexpected keyword argument 'query_text'
INFO: ... "POST /search HTTP/1.1" 500 Internal Server Error
```
→ **Вывод**: сигнатура метода `SearchService.search()` **не принимает аргумент `query_text`**, но клиент (CLI или тест) его передаёт.

##### **B. Ошибки в pytest-логах (клиентская часть):**
- `AttributeError: 'NoneType' object has no attribute 'lower'`  
  → `proc.stdout` или `proc.stderr` равны `None`.
- `TypeError: argument of type 'NoneType' is not iterable`  
  → попытка проверить `assert "текст" in proc.stdout`, но `stdout is None`.
- `TypeError: unsupported operand type(s) for +: 'NoneType' and 'str'`  
  → конкатенация `proc.stdout + proc.stderr` без проверки на `None`.

##### **C. UnicodeDecodeError в фоновом потоке чтения stdout/stderr:**
```
UnicodeDecodeError: 'charmap' codec can't decode byte 0x98 in position N: character maps to <undefined>
```
→ Происходит в `_readerthread` внутри `subprocess.py`.  
→ Причина: **Windows по умолчанию использует кодировку `cp1251`**, но CLI-приложение выводит **UTF-8** (включая символы, недопустимые в cp1251).

##### **D. Проблемы с текстовыми сравнениями:**
- Ожидалось: `'Очищено'`  
- Получено: `'РћС‡РёС‰РµРЅРѕ 15 Р·Р°РїРёСЃРµР№ РєСЌС€Р°\n'`  
→ Это **искажённый UTF-8 текст**, прочитанный как cp1251 → **декодирование прошло некорректно**.

##### **E. Сетевые ошибки:**
- `OSError: We couldn't connect to 'https://huggingface.co'`  
→ Тесты зависят от интернета, но **нет моков или условий пропуска при отсутствии сети**.

##### **F. Сигнатура `SearchService.search()` не соответствует вызову**
→ Возможно, в ветке `jina-embedding-v3` изменили сигнатуру (например, теперь используется `query` вместо `query_text`), но **вызывающий код не обновили**.

#### 🛠️ **3. Требования к исправлению**

##### **✅ Обязательно:**
1. **Исправить вызов `SearchService.search()`**:
   - Найти все места, где передаётся `query_text`.
   - Убедиться, что сигнатура метода совпадает с вызовом.
   - Если сигнатура изменилась — обновить вызывающий код (CLI, API-хендлеры).

2. **Исправить `subprocess.run()` во всех тестах**:
   - Добавить явные параметры:
     ```python
     subprocess.run(
         ...,
         encoding='utf-8',
         errors='replace',  # или 'ignore', но лучше 'replace'
         text=True,
     )
     ```
   - **Никогда не допускать `None` в `stdout`/`stderr`** при `text=True`.

3. **Обернуть все проверки `proc.stdout` в защиту от `None`**:
   ```python
   stdout = proc.stdout or ""
   stderr = proc.stderr or ""
   assert "Очищено" in stdout
   ```

4. **Убедиться, что CLI всегда выводит в UTF-8**, даже на Windows:
   - В `main.py` добавить в начало:
     ```python
     import sys
     import io
     if sys.stdout.encoding != 'utf-8':
         sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding='utf-8')
     if sys.stderr.encoding != 'utf-8':
         sys.stderr = io.TextIOWrapper(sys.stderr.buffer, encoding='utf-8')
     ```

5. **Добавить resilience для сетевых тестов**:
   - Для тестов, зависящих от Hugging Face или ВМ:
     ```python
     import pytest
     import socket

     def is_network_available(host="huggingface.co", port=443, timeout=5):
         try:
             socket.create_connection((host, port), timeout=timeout)
             return True
         except OSError:
             return False

     @pytest.mark.skipif(not is_network_available(), reason="No network")
     def test_sparse_encoder():
         ...
     ```

6. **Исправить сравнение строк в тестах**:
   - Не сравнивать байтовые искажения (`РћС‡РёС‰РµРЅРѕ`).
   - Убедиться, что **все строки читаются как UTF-8** → тогда `'Очищено' in stdout` будет работать.

##### **✅ Дополнительно (best practices):**
- Добавить в `pytest.ini`:
  ```ini
  [pytest]
  filterwarnings =
      ignore::pytest.PytestUnhandledThreadExceptionWarning
  ```
  → чтобы не засорять вывод, но **не скрывать реальные ошибки**.
- Добавить CI-проверку на Windows (если ещё нет).
- Убедиться, что все CLI-команды **всегда завершаются с ненулевым кодом при ошибке**, и **всегда выводят сообщение в stderr**.
