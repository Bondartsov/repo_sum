# repo_sum: RAG-as-a-Service Анализатор Кода

## Обзор проекта

**repo_sum** — это продвинутый инструмент для анализа кодовых репозиториев с использованием RAG (Retrieval-Augmented Generation). Он сочетает семантический поиск и возможности ИИ (OpenAI) для генерации документации, глубокого анализа кода и интеллектуальной навигации.

Проект построен на архитектуре **RAG-as-a-Service**:
*   **Локальный клиент:** Отвечает за сканирование файлов, локальный анализ и взаимодействие с пользователем (CLI и Web UI).
*   **Удаленный сервис (VM):** Развернут на выделенной виртуальной машине, выполняет ресурсоемкие задачи: генерацию эмбеддингов Jina v3 и хранение векторов в Qdrant.

**Основные возможности:**
*   **Семантический поиск:** Поиск по смыслу кода, а не только по ключевым словам.
*   **ИИ-анализ:** Автоматическое создание документации и объяснение логики кода через OpenAI.
*   **Гибридный поиск:** Комбинация плотных (векторных) и разреженных (ключевые слова) векторов для максимальной точности.
*   **Веб-интерфейс:** Интерактивное приложение на Streamlit для удобной работы.
*   **Автоматизация инфраструктуры:** Скрипт `vm_start.py` управляет SSH-подключениями, обновлениями и сервисами на удаленной VM.

## Ключевые файлы и директории

*   **`main.py`**: Главная точка входа для CLI. Управляет анализом, операциями RAG и проверкой статуса системы.
*   **`run_web.py`**: Запуск веб-интерфейса на базе Streamlit.
*   **`vm_start.py`**: Критически важная утилита для управления инфраструктурой VM (запуск, остановка, обновление, статус).
*   **`config.py`** и **`settings.json`**: Управление конфигурацией.
*   **`rag/`**: Основная логика RAG (клиенты эмбеддеров, векторное хранилище, поисковый сервис).
*   **`parsers/`**: AST-парсеры для поддерживаемых языков (Python, JS/TS, C#, C++).
*   **`tests/`**: Обширный набор тестов (Unit, Integration, RAG, VM).
*   **`AGENTS.md`**: Правила и контекст для ИИ-агентов, работающих с этим кодом.

## Сборка и запуск

### Предварительные требования
*   Python 3.8+
*   Зависимости из `requirements.txt` (`pip install -r requirements.txt`).
*   Настроенный файл `.env` (см. `.env.example`). Ключевые переменные: `OPENAI_API_KEY`, `VM_HOST`, `VM_USER`, `VM_PASSWORD`.

### Основные команды

**1. Инфраструктура и VM**
```bash
# Запуск и проверка статуса инфраструктуры на VM
python vm_start.py start
python vm_start.py status

# Обновление кода на VM
python vm_start.py update
```

**2. Веб-интерфейс (рекомендуется)**
```bash
python run_web.py
# Откроется по адресу http://localhost:8501
```

**3. CLI операции**
```bash
# Анализ репозитория
python main.py analyze ./path/to/repo

# Семантический поиск через RAG
python main.py rag search "логика подключения к базе данных"

# Проверка статуса RAG
python main.py rag status
```

**4. Тестирование**
```bash
# Запуск всех тестов
pytest

# Запуск тестов по категориям (см. pytest.ini)
pytest -m rag
pytest -m vm
pytest -m integration
```

## Конвенции разработки

*   **Стиль кода:** Соответствие стандарту PEP 8.
*   **Тестирование:** Активное использование `pytest`. Тесты помечены маркерами (например, `@pytest.mark.rag`, `@pytest.mark.vm`).
    *   **Unit-тесты:** Локальные, быстрые.
    *   **Интеграционные тесты:** Могут требовать доступ к VM или OpenAI API.
    *   **Асинхронность:** Использование `pytest-asyncio` для асинхронных компонентов.
*   **Архитектура:** Строгое разделение между локальным клиентом и удаленным сервисом. Взаимодействие через HTTP REST API.
*   **Документация:** `README.md` — основной источник информации о функциях, `AGENTS.md` — внутренний контекст для разработки.
