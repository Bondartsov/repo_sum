# 🤖 Субагенты проекта repo_sum

Этот документ описывает систему специализированных субагентов для проекта repo_sum.

## 📚 Что такое субагенты?

Субагенты - это специализированные роли AI-агентов, каждый из которых экспертен в своей области:
- **Архитектор** - проектирование архитектуры
- **Технический писатель** - документация
- **Тестировщик** - создание тестов

## 🚀 Как вызывать субагентов

### Вариант 1: Вручную через slash команды (рекомендуется)

Просто напишите в чате:

```
/architect Спроектируй архитектуру для модуля кэширования
```

```
/writer Обнови документацию для remote_embedder.py
```

```
/tester Создай unit тесты для hybrid_search функции
```

### Вариант 2: Основной агент вызывает автоматически

Основной агент (Claude) может сам вызывать субагентов когда видит необходимость:

**Пример:** Вы пишете "Добавь новую функцию для batch processing"
1. Claude вызывает `/architect` для проектирования
2. Реализует код сам
3. Вызывает `/tester` для создания тестов
4. Вызывает `/writer` для документирования

## 📋 Доступные субагенты

### 1. Архитектор (`/architect`)

**Файлы:**
- Документация: [architect.md](architect.md)
- Slash команда: [../commands/architect.md](../commands/architect.md)

**Специализация:**
- Проектирование архитектуры новых компонентов

**Примеры задач:**
```

/architect Проанализируй текущую архитектуру remote клиентов и предложи улучшения

/architect Как лучше реализовать retry механизм для VM запросов?
```

## 🔄 Типичные workflow

### Workflow 1: Добавление новой функции

```
Пользователь: "Добавь функцию batch processing для эмбеддингов"

1. /architect
   → Проектирует архитектуру batch processing
   → Определяет интерфейсы и зависимости
   → Обновляет Technical Architecture.md

2. Основной агент (разработчик)
   → Реализует код согласно архитектуре
   → Следует SOLID принципам

3. /tester
   → Создает unit тесты (offline, моки)
   → Создает integration тесты
   → Обеспечивает покрытие ≥90%

4. /writer
   → Пишет docstrings на русском
   → Обновляет README с примерами
   → Документирует API
```

### Workflow 2: Исправление бага

```
Пользователь: "RemoteVMEmbedder падает на больших батчах"

1. /tester
   → Создает тест воспроизводящий баг
   → Убеждается что тест падает

2. Основной агент
   → Исправляет баг в коде
   → Проверяет что тест теперь проходит

3. /tester
   → Добавляет regression тесты
   → Проверяет edge cases

4. /writer
   → Обновляет troubleshooting в документации
   → Добавляет примечание в changelog
```

### Workflow 3: Рефакторинг

```
Пользователь: "Отрефактори query_engine.py для лучшей читаемости"

1. /architect
   → Анализирует текущую структуру
   → Предлагает улучшения архитектуры
   → Создает план рефакторинга

2. Основной агент
   → Выполняет рефакторинг
   → Сохраняет обратную совместимость

3. /tester
   → Обновляет тесты под новые интерфейсы
   → Проверяет что все тесты проходят

4. /writer
   → Обновляет документацию
   → Исправляет устаревшие примеры
```

## 💡 Когда основной агент должен вызывать субагентов

### Автоматически вызывать `/architect`:
- ✅ Пользователь просит **спроектировать** что-то новое
- ✅ Обсуждается изменение **архитектуры**
- ✅ Нужно выбрать **технологию** или **паттерн**
- ✅ Требуется принять **архитектурное решение**
- ✅ Нужно создать **ADR** (Architecture Decision Record)

### Автоматически вызывать `/writer`:
- ✅ Добавлен **новый функционал** (нужна документация)
- ✅ Изменен **существующий код** (обновить документацию)
- ✅ Пользователь просит **объяснить** или **задокументировать**
- ✅ Нужно создать **README** или **гайд**
- ✅ Отсутствуют **docstrings** или **комментарии**

### Автоматически вызывать `/tester`:
- ✅ Написан **новый код** (нужны тесты)
- ✅ Исправлен **баг** (нужен regression тест)
- ✅ Изменены **интерфейсы** (обновить тесты)
- ✅ Пользователь просит **написать тесты**
- ✅ Покрытие **упало ниже 90%**

## ⚠️ Важные замечания

### Для всех субагентов:
- ✅ **Русский язык** - все комментарии, docstrings, документация
- ✅ **Windows/PowerShell** - все команды в PowerShell синтаксисе
- ✅ **RAG-as-a-Service** - учитывать VM архитектуру
- ✅ **Обновление документов** - всегда обновлять связанные файлы

### Специфичные правила:

**Архитектор:**
- ❌ Не нарушать RAG-as-a-Service архитектуру
- ❌ Не менять размерность векторов (1024d - стандарт)
- ✅ Обновлять `rules/Technical Architecture.md`

**Технический писатель:**
- ❌ Не использовать bash команды (только PowerShell)
- ❌ Не показывать Unix пути (только Windows)
- ✅ Все примеры кода должны работать

**Тестировщик:**
- ❌ Unit тесты не должны делать HTTP запросы
- ❌ Не хардкодить localhost (использовать os.getenv())
- ✅ Async методы мокировать через async функции
